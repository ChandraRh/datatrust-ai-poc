What it catches

Problems that quietly shrink your numbers

Each of these passes a normal pipeline run. DataTrust AI finds it, proves the cause and sizes it in money. Examples from the sample data it is tested on.

HIGH

Empty currency

9 payments arrive with no currency and are held back. Revenue is ₹6,401.15 short of what the gateway settled.

Fix: the currency is taken from each payment's own order, after an admin approves.
HIGH

Typo in a status

3 payments say CAPTRED instead of CAPTURED. They never reach the report, which is ₹3,186.00 short.

Found by: the status rule, with every held-back row listed.
MEDIUM

Negative amounts

4 orders arrive with a sign error and are held back before they distort revenue.

Fix: the amount actually paid, shown row by row before anything changes.
LOW

Duplicate payments

6 payments are sent twice. The copies are removed and settlement still matches.

Found by: the unique-key rule.
CRITICAL

A pipeline that keeps failing

An Azure Data Factory pipeline fails five runs in a row. The Azure error is explained in plain words, with what to do next.

Found by: the run checks on every factory.
MEDIUM

Columns that drifted

A copy succeeds, but the file and the target table no longer have the same columns.

Found by: the after-run check on source and target.

Explainable by design

A trust score that shows its working

Every source, from a database to an ADF factory, is scored the same way. Each subject gets a mark from the checks that ran, the score is their average, and a serious open problem sets a ceiling so it is never averaged away.

90+ Healthy75–89 Needs attentionBelow 75 At risk
  • Critical open issue: the score stays at 74 or below
  • High open issue: the score stays at 89 or below
  • A subject with nothing measured is left out, never counted as 0

Enterprise ready

Built for governed data teams

Its checks only read. The changes it can make, a data fix or an access grant, show the exact SQL first and run only after an admin approves.

Secure sign-in

Email sign-in with verification, Google sign-in, and sessions held in HTTP-only cookies.

Role-based access

Admins connect sources and approve changes; viewers explore. Access to data is requested and granted in the app.

Approval before change

Auto-fixes, grants and new users are previewed with the exact SQL and run only after an admin approves.

Complete audit trail

Sign-ins, connections, approvals and fixes are logged with who did what and when.

Secrets stay with you

Passwords and keys live in your environment or secret store. DataTrust keeps only the variable's name.

Alerts with owners

Incidents reach Google Chat with an owner and a time to fix, and a reminder when they run late.
